# Parkour Plugin (Paper, Minecraft 1.21.11, JDK 25)

Серверная адаптация части механик клиентского Fabric-мода **parkourmod**
(рывок, скольжение, фиксация/бег по стене, отскок от стены, залезание на уступ,
разбег). Это не автоматическая конвертация — мод и плагин работают на
принципиально разных платформах, подробности ниже.

## Почему это не "тот же мод, только как плагин"

Клиентский мод каждый тик подменял скорость игрока (`LocalPlayer.setDeltaMovement`)
на основе сырых состояний клавиш (`Options.keyShift.isDown()` и т.п.) и рисовал
кастомные анимации/камеру/HUD/меню настроек через миксины в рендер-классы клиента.
На выделенном Paper-сервере (headless, без графики) для этого физически нет ни
классов, ни данных:

| Возможность мода | На сервере |
|---|---|
| Собственные привязываемые клавиши (R, K и т.п.) | **Недоступно.** Сервер получает только дискретные события (прыжок, сик, спринт) и позицию — не "какая клавиша нажата" |
| Удержание W ("вперёд") | **Недоступно** как таковое — сервер не знает, что именно зажато, только куда игрок фактически движется |
| sneak / sprint / onGround | **Доступно** как живые, постоянно актуальные флаги — почти как в моде |
| Камера (тряска, наклон, FOV) | **Невозможно** — сервер не рендерит картинку игроку |
| Анимации персонажа от третьего лица (Emotecraft) | **Невозможно** — нужен рендер-пайплайн клиента |
| Меню настроек (Mod Menu / Cloth Config) | **Невозможно** без своего клиентского мода |
| Поза "лёжа" при скольжении | **Невозможно** штатно — со стороны сервер видит обычную стоящую/бегущую анимацию |
| Физика толчков/скорости (`setVelocity`) | **Доступна и работает** — единицы скорости в Bukkit те же (блоки/тик), что и в клиенте, поэтому все дистанции/формулы (в т.ч. точная формула дальности рывка `dashSpeedFor`) перенесены без пересчёта |

Т.е. плагин ниже — это честная **новая серверная реализация** тех же по духу
механик, использующая то, что реально видно серверу, а не байт-в-байт
перенесённый код. Некоторые жесты пришлось переизобрести под то, что доступно
Bukkit/Paper API.

## Как теперь управлять (карта жестов)

| Было в моде | Стало в плагине |
|---|---|
| **G** — вкл/выкл режим | команда **/parkour** (алиас `/pk`) |
| **R** на бегу — разбег | клавиша "поменять предметы местами" (по умолчанию **F**) во время спринта |
| **Прыжок+Шифт**, держать/отпустить — рывок | сидя (**Шифт**) на земле нажать **Прыжок** — начнётся заряд (индикатор в action bar); отпустить **Шифт** — рывок на выбранную дистанцию |
| **Шифт** на бегу — скольжение | начать **Шифт** во время спринта (работает и в обратном порядке — заспринтить, уже сидя) |
| **Шифт** в воздухе у стены — фиксация | то же самое: **Шифт** в воздухе рядом со стеной |
| **Прыжок** при фиксации/беге по стене — отскок | то же самое |
| **W** у края стены при фиксации — залезть | происходит **автоматически**, как только найден уступ (клавиша W серверу не видна) |
| Разбег + прыжок на стену, держать W — бег по стене | автоматически, пока активен разбег и скорость выше порога |

Камера, анимации персонажа, меню настроек, поза при скольжении, полностью
переназначаемые клавиши — **не реализованы**, см. таблицу выше.

## Структура проекта

```
parkour-plugin/
├── build.gradle.kts
├── settings.gradle.kts
└── src/main/
    ├── java/com/parkourmod/plugin/
    │   ├── ParkourPlugin.java     — главный класс
    │   ├── ParkourConfig.java     — загрузка config.yml
    │   ├── ParkourState.java      — состояние одного игрока
    │   ├── ParkourEngine.java     — вся логика механик (тик-луп)
    │   ├── ParkourListener.java   — Bukkit-события → вызовы Engine
    │   ├── ParkourCommand.java    — /parkour, /parkour reload
    │   └── WallUtils.java         — упрощённый поиск стен/уступов
    └── resources/
        ├── plugin.yml
        └── config.yml
```

## Сборка в IntelliJ IDEA

1. **File → Open** → выбрать папку `parkour-plugin` → «Trust Project».
   IntelliJ сам распознает Gradle-проект (Kotlin DSL) и подтянет `gradlew`.
2. **File → Project Structure → SDK**: должен быть указан **JDK 25**
   (Amazon Corretto / Temurin / Oracle — не важно, важна версия).
   Если JDK 25 не установлен — IntelliJ предложит скачать его сам
   (**Project Structure → SDKs → + → Download JDK → 25**).
3. **Settings → Build Tools → Gradle**: Gradle JVM — тоже **JDK 25**
   (или "Project SDK", если он уже = 25).
4. Дождаться Gradle sync (первый раз скачает Paper API ~первые десятки МБ —
   нужен интернет до `repo.papermc.io`).
5. Собрать: **Gradle (панель справа) → Tasks → build → build**,
   либо в терминале: `./gradlew build`.
6. Готовый jar: `build/libs/parkour-plugin-1.0.0.jar`.
   Положить его в папку `plugins/` вашего Paper-сервера 1.21.11 (JDK 25)
   и перезапустить сервер.

### Быстрая проверка локально (необязательно)
Можно добавить в `build.gradle.kts` плагин `xyz.jpenilla.run-paper`, чтобы
Gradle сам скачал тестовый Paper-сервер и запускал его задачей `runServer`
прямо из IntelliJ — но версии таких Gradle-плагинов быстро меняются, поэтому
в проект она не включена. Проще всего просто вручную поднять тестовый Paper
1.21.11 и скопировать jar в его `plugins/`.

## Настройка

Все числовые параметры (дальности рывка/скольжения, скорости, время
перезарядок) — в `plugins/ParkourPlugin/config.yml` после первого запуска.
Значения по умолчанию взяты из `ParkourConfig.java` исходного мода, так что
"на ощупь" дистанции должны совпадать. После правки: `/parkour reload`
(нужны права `parkourmod.reload`, по умолчанию — у op).

## Известные упрощения геометрии

Поиск стен и уступов (`WallUtils`) сделан через проверку блоков по сетке
(`Material#isSolid()` в паре точек), а не через точное сравнение AABB игрока
с коллизией мира, как в оригинале. На большинстве обычных стен/углов это
незаметно, но на сложной геометрии (тонкие заборы, ступени, полублоки)
поведение может немного отличаться от клиентского мода.
